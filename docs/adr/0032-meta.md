# ADR 0032: Meta: staged connections, consent before the Conversions API, WhatsApp before SMS

- Status: Accepted
- Date: 2026-10-31
- Plan: phase-9-plan §2.1, §3, Q1, Q4–Q8. Code: `packages/shared/src/channels/`, `packages/db/src/schema/channels.ts`, and from stage 1's later steps `packages/providers/src/meta/` and `packages/core/src/channels/`
- Builds on: ADR 0010 (outbox), ADR 0013 (free plan), ADR 0024 (credentials vault), ADR 0025 (notifications), ADR 0030 (believe only the provider's answer)

## Context

Most of the pilot's orders start in a Facebook, Messenger or WhatsApp chat. The owner asked for the highest integration Meta allows, built step by step. Three things shape the design:

- **Meta's approvals take weeks.** Business verification, Tech Provider status and app review must come before the platform can act for a store through its own Meta app. Work that needs none of them should not wait.
- **Shoppers' data leaves the platform.** The Conversions API sends hashed contact details, the shopper's IP and browser to Meta. The storefront already asks for cookie consent before the pixel loads (phase-3-plan §3.10).
- **Messages cost money and can arrive twice.** WhatsApp templates are billed per message to the store (from October 2026, about $0.0037 a utility template in Bangladesh), SMS costs the store per text, and every queue delivers at least once.

## Decision

1. **Five stages, each useful alone** (phase-9-plan §3):
   - stage 1 needs no Meta app: chat links, the feed, the checkout URL, and the Conversions API with a token the store pastes;
   - stage 2 sends WhatsApp with the store's own app and token;
   - stage 3 replaces both with the platform's reviewed app, one-click connection and one webhook.
2. **Consent decides the Conversions API.** Checkout records `orders.attribution` (the `_fbp` and `_fbc` cookies, the first landing's UTM fields, Meta's `cart_origin`) only when the shopper accepted the banner, and no server event is ever sent without it (Q4). Attribution is cleared after 30 days, and at anonymization.
3. **One event per order and name.** `store.meta_events` holds a row per order for `Purchase` and `Delivered`, unique per store, order and name. A redelivered outbox event finds the row and sends nothing. The event ID Meta sees is the order ID, the same as the browser pixel's, so Meta keeps one of the two.
4. **When a purchase is reported is the store's choice** (Q5): when placed, as the pixel does (the default), or when confirmed, so ads learn from real COD orders. A custom `Delivered` event is optional.
5. **The feed's key is the server's.** It is made the first time the feed is turned on, kept when the feed is turned off and on again, and never taken from a settings patch. The feed holds only what the storefront shows, and the key stops a whole catalog being scraped in one request.
6. **A Meta webhook is checked by its signature** (`X-Hub-Signature-256` with the app secret, in constant time, before parsing), and believed only about Meta's own objects (a message arrived, was delivered, was read). Anything that changes an order, such as a Confirm button, carries the platform's own signed token, checked as the SMS confirmation link is (stage 2).
7. **WhatsApp first, SMS only as a fallback** (Q7): the SMS for the same event waits, and is sent only if WhatsApp fails or says nothing within 10 minutes. The delivery log stays the idempotency (ADR 0025). Inside an open 24-hour window, a plain message replaces the now-charged utility template while the month's free service messages last.
8. **Each store pays Meta directly** (Q8), through its own WhatsApp account. The platform never resells messages.

## Consequences

- **Stages 1 and 2 build and run without any approval from Meta.** Until the store pastes a token, nothing is sent.
- **Some ad measurement is lost** for shoppers who declined cookies. The store's privacy page stays true.
- **Two new store tables** (`feeds`, `meta_events`) join the isolation suite, the export and the purge (migrations 0048 and 0049).
- **The daily cleanup** clears an order's IP, browser and attribution at 90 days first, then attribution alone from 30 days. Each update leaves a row that `mm_system`'s policy allows.
- **Stage 3 replaces stage 2's per-store webhook** with one platform webhook, routed by WhatsApp account, Page and Instagram IDs. Stage 2's paste-in connection stays for previews and for stores that keep their own app.
